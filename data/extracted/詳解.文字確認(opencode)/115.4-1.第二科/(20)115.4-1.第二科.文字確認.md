## 題目（來源：考卷 PDF 第 5 頁）

在規劃生成式 AI 解決方案時，下列何種應用場景最適合採用 GPT-Realtime 類型模型？

(A) 需長時間批次處理的大規模報表生成任務；
(B) 即時資料查詢與結構化資訊檢索系統；
(C) 即時語音客服與互動式 AI 代理；
(D) 以高一致性為優先的法規文件自動摘要

**官方答案：C（即時語音客服與互動式 AI 代理）**

## 1. 場景與關鍵字（上方）

- 場景：依模型特性選擇合適應用場景，判斷 GPT-Realtime（語音到語音、低延遲）最適合哪一類任務。
- 關鍵字：**GPT-Realtime**、**語音到語音（speech-to-speech）**、低延遲、**voice agent**、**客服（customer support）**、即時互動、工具呼叫（function calling）、SIP 電話、批次處理對比。

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A 長時間批次報表生成 | ❌ 錯誤 | 批次報表重視吞吐量與成本，不需要即時語音互動；OpenAI 官方將 gpt-realtime 定位為 production-ready voice model，非批次報表工具。 |
| B 即時資料查詢與結構化資訊檢索 | ❌ 錯誤 | 結構化查詢／檢索應走一般 API 或 RAG／資料庫查詢；Realtime API 的價值在語音對話，不是結構化檢索。 |
| C 即時語音客服與互動式 AI 代理 | **最正確** | OpenAI 官方（2025-08-28）：gpt-realtime 與客戶共同訓練，專為 customer support、personal assistance、education 等真實語音任務優化；Realtime API 以單一模型直接處理與生成音訊，降低延遲。 |
| D 高一致性法規文件摘要 | ❌ 錯誤 | 法規摘要要求可追溯與一致性，應使用文字模型加標準流程；語音模型的即時性在此無助益。 |

## 3. 錯置選項（紅框）與未來選答規則

- A 是**批次／即時錯置**：Realtime 的優勢不是批次處理。
- B 是**語音／檢索錯置**：結構化檢索不需要 speech-to-speech。
- D 是**一致性／即時性錯置**：法規摘要重精確可稽核，不是 conversational latency。
- 未來選答規則：
  1. 題目出現 Realtime / 語音 / voice agent / 客服 → 優先選即時語音互動。
  2. 題目出現批次、結構化查詢、法規一致性 → 排除即時語音模型。
  3. 記得官方定位：speech-to-speech、低延遲、可呼叫工具、可接 SIP 電話。
- 本題唯一符合官方產品定位的是 C。
