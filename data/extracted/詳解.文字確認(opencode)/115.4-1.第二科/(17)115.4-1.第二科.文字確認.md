## 題目（來源：考卷 PDF 第 4 頁）

某企業提供大型語言模型（LLM）API 服務，需支援高併發請求與流量波動，同時要求服務不中斷並具備故障容忍能力。若以高可用性與可擴展性為主要設計原則，下列哪一種部署方式較為適當？

(A) 採用單一高效能虛擬機（VM）集中部署，以提升資源使用效率；
(B) 建立多個模型服務實例並透過負載分散機制提供服務；
(C) 將推論任務改由用戶端設備分擔，以降低伺服器負載壓力；
(D) 使用 FTP 協議傳輸請求與回應，以減少服務通訊負擔

**官方答案：B（建立多個模型服務實例並透過負載分散機制提供服務）**

## 1. 場景與關鍵字（上方）

- 場景：企業對外提供 LLM API，面臨高併發、流量波動，要求服務不中斷且具有故障容忍；屬於推論服務的高可用（HA）與水平擴充設計題。
- 關鍵字：**高併發**、流量波動、**服務不中斷**、故障容忍、高可用（High Availability）、可擴展性（Scalability）、**多實例**、**負載分散／負載平衡**、自動擴充、健康檢查與容錯移轉、單點故障（SPoF）。

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A 單一高效能 VM 集中部署 | ❌ 錯誤 | 單一實例即**單點故障**；AWS SageMaker 官方建議正式環境每個端點部署多個實例並分散至不同可用區，以達到高可用。 |
| B 多個模型服務實例＋負載分散 | **最正確** | AWS Well-Architected Generative AI Lens「GENREL05-BP01 Load-balance inference requests」明確指出：以負載平衡與橫向擴展提升可用性，跨區域／可用區分散推論請求，搭配健康檢查與自動容錯移轉。 |
| C 推論改由用戶端設備分擔 | ❌ 錯誤 | 用戶端設備能力與可用性不可控，且題幹要求是「API 服務不中斷」；把負載推給用戶端並未解決伺服器端高可用與故障容忍。 |
| D 使用 FTP 傳輸請求與回應 | ❌ 錯誤 | FTP 是檔案傳輸協定，不是 API 請求／回應的通訊設計；更與高可用、負載分散無關。 |

## 3. 錯置選項（紅框）與未來選答規則

- A 是**單點故障**：高效能 ≠ 高可用，硬體再強仍會故障。
- C 是**責任錯置**：把推論丟給用戶端，無法保證服務端 SLA。
- D 是**協定錯置**：FTP 與 API 通訊、可用性設計無關。
- 未來選答規則：
  1. 看到「不中斷／故障容忍」→ 先排除單一實例。
  2. 看到「高併發／流量波動」→ 找「多實例＋負載平衡＋自動擴充」。
  3. 看到奇怪協定（FTP）或把責任推給用戶端 → 直接排除。
- 本題唯一同時滿足高可用與可擴展性的是 B。
