## 題目（來源：考卷 PDF 第 9 頁）

某連鎖餐廳開發 AI代理（AI Agent）協助處理顧客訂位需求。設計人員要求 AI Agent 在查詢訂位系統前，先分析顧客需求並決定查詢策略，再呼叫訂位系統查詢；每次取得查詢結果後，AI Agent 皆需重新判斷是否需要查詢其他時段，或直接回覆可訂位的時間。請問設計人員採用的是下列哪一種框架概念？

(A) Reasoning and Acting（ReAct）；
(B) Retrieval-Augmented Generation（RAG）；
(C) Prompt Chaining；
(D) Zero-Shot Prompting

**官方答案：A（Reasoning and Acting（ReAct））**

## 1. 場景與關鍵字（上方）

- 場景：訂位 AI Agent 的行為是「**先推理需求與策略→呼叫工具（訂位系統）→取得 Observation→再推理是否繼續查詢或回覆**」的反覆迴圈；題目問此框架概念。
- 關鍵字：ReAct、Thought／Action／Observation 交錯、Yao 等人 2022（ICLR 2023）、工具呼叫、動態調整計畫、RAG、Prompt Chaining、Zero-Shot

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A Reasoning and Acting（ReAct）； | **最正確** | ReAct 的核心就是讓模型交錯產生推理軌跡（Thought）與任務動作（Action），並根據環境回饋（Observation）更新計畫、處理例外。題幹「分析需求→呼叫訂位系統→依結果再判斷」完全對應 Thought→Action→Observation→Thought 迴圈。 |
| B Retrieval-Augmented Generation（RAG）； | ❌ 錯誤 | RAG 是「先檢索文件再把內容交給 LLM 生成」，重點在知識增強；本題是反覆呼叫工具並依結果調整行動，不是文件檢索生成。 |
| C Prompt Chaining； | ❌ 錯誤 | Prompt Chaining 是把任務拆成固定順序的提示步驟，前一步輸出接續下一步；題幹強調「每次取得結果後重新判斷」，代表流程不是預先固定的鏈，而是動態決策。 |
| D Zero-Shot Prompting | ❌ 錯誤 | Zero-Shot 只是不使用範例的提示方式，無法描述這種推理與行動交錯的代理框架。 |

## 3. 錯置選項（紅框）與未來選答規則

- B 是**框架混淆**：把工具呼叫代理誤當成文件檢索生成。
- C 是**彈性不足**：固定提示鏈無法表現「依結果再決定下一步」的迴圈。
- D 是**層級不足**：Zero-Shot 是提示方式，不是代理框架。

- 未來選答規則：
  1. 看到「推理→呼叫工具→觀察結果→再推理」的迴圈→ 想 ReAct；
  2. 看到「查知識庫／文件再生成」→ 想 RAG；
  3. 看到「依序執行固定步驟、前一步輸出接下一步」→ 想 Prompt Chaining；
  4. 看到「不給範例」→ 才是 Zero-Shot。
