## 題目（來源：考卷 PDF 第 10–11 頁）

某單位需要整理數百頁會議紀錄，希望生成式 AI能先整理各章節重點，再逐步整合為完整摘要，以兼顧整體內容的前後脈絡與成本考量。下列何者為此作法的主要優點？

(A) 能逐步整合各章節的重要資訊，在處理長篇內容時較能維持整體脈絡與重點的一致性；
(B) 先將整份文件濃縮為單一摘要，再直接依摘要產生最終結果，可完整保留所有原始細節；
(C) 將各章節分別摘要後直接作為最終結果，不再整合各章節內容，即可維持全文前後脈絡 ；
(D) 一次將整份文件完整輸入模型進行摘要，通常比逐步整合摘要更能降低運算成本

**官方答案：A（能逐步整合各章節的重要資訊，在處理長篇內容時較能維持整體脈絡與重點的一致性）**

## 1. 場景與關鍵字（上方）

- 場景：數百頁會議紀錄要摘要：作法是「**先分章節摘要→再逐步整合成完整摘要**」，兼顧前後脈絡與成本；題目問此法的主要優點。
- 關鍵字：MapReduce／Refine 階層式摘要、長文件、chunk、context window、脈絡一致性、成本、Stuff 一次輸入的限制

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A 能逐步整合各章節的重要資訊，在處理長篇內容時較能維持整體脈絡與重點的一致性； | **最正確** | 先分塊摘要再逐步整合，正是 LangChain 的 map_reduce／refine 模式：map_reduce 先平行摘要各 chunk 再 reduce 成最終摘要；refine 則按順序把新章節與既有摘要合併，能保留敘事順序與跨章節脈絡。A 精確說出「逐步整合以維持脈絡與重點一致性」。 |
| B 先將整份文件濃縮為單一摘要，再直接依摘要產生最終結果，可完整保留所有原始細節； | ❌ 錯誤 | 摘要本質是壓縮，不可能「完整保留所有原始細節」；且「先濃縮為單一摘要再直接產出」正是題目要避免的做法。 |
| C 將各章節分別摘要後直接作為最終結果，不再整合各章節內容，即可維持全文前後脈絡 ； | ❌ 錯誤 | 只把各章節摘要直接當最終結果、不再整合，就失去跨章節的整體脈絡，與題幹「逐步整合為完整摘要」矛盾。 |
| D 一次將整份文件完整輸入模型進行摘要，通常比逐步整合摘要更能降低運算成本 | ❌ 錯誤 | 一次輸入整份文件受限於 context window，且每次呼叫都要帶完整長文本，成本不一定較低；LangChain 文件指出 stuff 最便宜但僅在文本放得下時適用，map_reduce／refine 才是超過 context window 的方案。 |

## 3. 錯置選項（紅框）與未來選答規則

- B 是**矛盾與誇大**：壓縮不能完整保留細節，且做法與題幹相反。
- C 是**少了整合步驟**：直接拼接章節摘要會失去跨章節脈絡。
- D 是**成本判斷反了**：長文件一次輸入受限於 context window，也不必然更便宜。

- 未來選答規則：
  1. 看到「先分章節／分塊摘要再整合」→ 想 MapReduce／Refine 階層式摘要；
  2. 看到「完整保留所有細節」「不再整合」→ 通常是絕對化干擾項；
  3. 看到「一次輸入全部最省」→ 要注意 context window 與 Token 成本；
  4. 題目問「主要優點」時，優點要對應題幹的「前後脈絡＋成本」兩件事。
