## 題目（來源：考卷 PDF 第 9–10 頁）

某金融集團建構了多代理（Multi-Agent）AI 系統，由不同的 Agent 分別負責市場分析、風險評估與交易執行。系統架構師發現，當 Agent A 完成市場分析後更新了判斷，Agent B 的風險評估卻仍基於舊資訊，最終導致 Agent C 執行了不一致的交易策略。這種現象最根本的成因是什麼？

(A) 各 Agent 之間缺乏有效的上下文（Context）同步機制，導致各自持有不一致的資訊狀態進行決策；
(B) Agent B 與 Agent C 的伺服器記憶體不足，無法即時載入 Agent A 傳遞的最新資訊；
(C) 三個 Agent 使用了不同廠商的語言模型，各平台的上下文（Context）格式互不相容；
(D) 系統中部分 Agent 的上下文視窗（Context Window）較小，影響其回應完整性，但不會影響各 Agent 之間的資訊同步機制

**官方答案：A（各 Agent 之間缺乏有效的上下文同步機制，導致各自持有不一致的資訊狀態進行決策）**

## 1. 場景與關鍵字（上方）

- 場景：金融多代理系統中，Agent A 更新判斷後，Agent B 仍用舊資訊、Agent C 據此執行不一致策略；問**最根本原因**。
- 關鍵字：**多代理共享狀態（shared state）**、**上下文同步／一致性（context synchronization）**、stale read（讀到過期資訊）、race condition、**並行控制（concurrency control）**、「各自持有不一致資訊狀態」；記憶體不足、模型廠商格式、context window 大小皆非根本原因。

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A 缺乏有效的上下文同步機制 | **最正確** | 題幹描述的是典型「stale read／狀態不一致」：A 更新後 B、C 未取得最新狀態；多篇多代理研究指出共享狀態的同步與並行控制是此類矛盾的根源。 |
| B 伺服器記憶體不足 | ❌ 錯誤 | 把系統設計問題歸咎於硬體資源；若無同步機制，即使記憶體充足仍會讀到舊資訊。 |
| C 不同廠商模型、格式不相容 | ❌ 錯誤 | 格式不相容不是題幹核心；即使格式相同，沒有同步／版本機制仍會產生舊資訊。 |
| D 部分 Agent 上下文視窗較小 | ❌ 錯誤 | 選項自己還說「不會影響資訊同步機制」，等於承認與題幹現象無關；context window 大小影響單一回應完整性，不解釋跨代理狀態落差。 |

## 3. 錯置選項（紅框）與未來選答規則

- B 是**硬體歸因**：把軟體架構的同步問題誤當成記憶體不足。
- C 是**格式歸因**：不同模型格式可以用中介層處理，不是「最根本」原因。
- D 是**自相矛盾選項**：結尾明說「不會影響同步」，等於自我排除。
- 未來選答規則：
  1. 看到多代理「更新後別人還用舊資訊」→ 找**上下文／共享狀態同步機制**。
  2. 出現「記憶體不足」「不同廠商格式」「context window 太小」→ 屬基層環境或單體限制，非跨代理協調根本原因。
  3. 選項若出現「但不會影響……」的自我否定句，通常可直接排除。
  4. 關鍵術語：stale read、lost update、concurrency control、versioning。
