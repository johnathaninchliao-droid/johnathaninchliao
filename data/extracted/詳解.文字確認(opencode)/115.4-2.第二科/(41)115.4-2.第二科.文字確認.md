## 題目（來源：考卷 PDF 第 11 頁）

某軟體顧問公司正在為客戶規劃一套 Agentic AI 專案管理系統，用於協助 AI 代理（AI Agent）自主完成跨部門任務協調。在系統設計過程中，團隊採用解決方案圖（Solution Graph）作為任務與決策的結構表示，並由大型語言模型（LLM）負責推理與行動生成。請問下列何者最能說明 LLM 與 Solution Graph 之間的關係？

(A) LLM 可根據問題進行推理，產生任務步驟與其關聯，並據此協助建構 Solution Graph 作為後續行動規劃依據；
(B) LLM 主要擅長生成自然語言內容，對於結構化任務關係的建構能力有限，通常不參與 Solution Graph 的形成；
(C) Solution Graph 主要由系統依既定流程與規則生成，LLM 不參與其結構建構，僅提供輔助資訊；
(D) LLM 主要負責人機對話與回應生成，並不參與任務規劃或 Solution Graph 的建立

**官方答案：A（LLM 可根據問題進行推理，產生任務步驟與其關聯，並據此協助建構 Solution Graph 作為後續行動規劃依據）**

## 1. 場景與關鍵字（上方）

- 場景：Agentic AI 系統以 **Solution Graph** 表示任務與決策，並由 **LLM 負責推理與行動生成**；問兩者關係。
- 關鍵字：**LLM 推理產生任務步驟與關聯→建構 Solution Graph→做為行動規劃依據**、planner agent、**否定 LLM 參與的選項（B／C／D）皆偏限**、結構化輸出（如 Mermaid／DAG）能力。

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A LLM 推理產生步驟與關聯，協助建構 Solution Graph | **最正確** | 在 Agentic 架構中，LLM 扮演 planner 角色，把目標拆解為子任務並輸出結構化依賴（即 Solution Graph），供後續行動規劃；與第 40 題對 Solution Graph 的定義相互呼應。 |
| B LLM 不參與 Solution Graph 形成 | ❌ 錯誤 | 與題幹「由 LLM 負責推理與行動生成」直接矛盾；當代 LLM 具備結構化任務關係生成能力。 |
| C 系統依既定規則生成，LLM 僅提供輔助資訊 | ❌ 錯誤 | 把 LLM 降級為輔助角色，忽略其任務拆解與推理的核心職責。 |
| D LLM 只做對話，不參與任務規劃或建立圖譜 | ❌ 錯誤 | 同樣與題幹矛盾；LLM 在 Agentic 系統中不只是聊天介面。 |

## 3. 錯置選項（紅框）與未來選答規則

- B、C、D 都是**貶低 LLM 角色**的選項，分別說「能力有限」「不參與建構」「不參與規劃」；三者都與題幹「LLM 負責推理與行動生成」衝突。
- 本題與第 40 題成對：第 40 題問「Solution Graph 是什麼（DAG）」，本題問「誰建構它（LLM）」，兩題答案互相支撐。
- 未來選答規則：
  1. 看到「LLM 與 Solution Graph 的關係」→ 找**LLM 推理→產生步驟與關聯→建構圖譜→供行動規劃**。
  2. 出現「不參與」「能力有限」「僅提供輔助」「只負責對話」→ 凡否定 LLM 規劃角色的選項，優先排除。
  3. 記得 Agentic 系統中 LLM 常兼任 planner，而不是單純的回應生成器。
