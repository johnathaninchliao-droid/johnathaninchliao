## 題目（來源：考卷 PDF 第 2 頁）

一家連鎖零售業者使用某封閉式 No-Code 平台多年，將客戶資料、訂單流程與內部作業高度整合於該平台。近期業者進行系統盤點時發現，該平台資料採專有格式儲存，匯出功能有限，且未提供標準 API 支援。在此情境下，長期而言，該企業最可能面臨下列何種風險？

(A)員工需具備撰寫進階程式語法的能力，才能持續使用該平台進行系統操作；
(B)隨著系統使用時間增加，平台運算效能將逐漸下降，影響營運效率；
(C)系統運作過程中較容易發生資安漏洞，導致資料外洩風險提高；
(D)企業在未來更換系統時，將因資料與功能難以轉移而高度依賴原平台

**官方答案：D（未來更換系統時，將因資料與功能難以轉移而高度依賴原平台）**

## 1. 場景與關鍵字（上方）

- 場景：連鎖零售業長期使用封閉式 No-Code 平台，客戶資料與流程高度整合；盤點發現專有格式、匯出有限、缺乏標準 API，要求判斷長期最主要風險。
- 關鍵字：**封閉式平台**、**供應商鎖定（Vendor lock-in）**、專有格式、匯出功能有限、缺乏標準 API、轉換成本、長期風險

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A 需寫進階程式才能操作 | ❌ 錯 | No-Code 的賣點正是降低撰寫程式的需求；專有格式與 API 問題反而表示難以自行用程式取出資料。 |
| B 使用越久效能越差 | ❌ 錯 | 平台效能是否下降取決於架構與容量，並非「使用時間」必然結果；題幹也未給出效能資訊。 |
| C 資安漏洞風險提高 | ❌ 錯 | 封閉格式不等於漏洞較多；題幹沒有提到權限、修補或外洩事件，屬過度推論。 |
| D 難以轉移而依賴原平台 | **最正確（正解）** | 專有格式＋有限匯出＋無標準 API 正是 vendor lock-in 的典型成因；Wikipedia 條目定義為因轉換成本過高而依賴單一供應商。 |

## 3. 錯置選項（紅框）與未來選答規則

- A 與 No-Code 的定義相反：平台降低而非提高程式能力需求。
- B、C 是常見但無根據的推測；題幹提供的是「資料可攜性」線索，不是效能或資安線索。
- 未來選答規則：看到「專有格式／無法匯出／無標準 API／高度整合」，直接聯想供應商鎖定與轉換成本，不要聯想員工技能或資安。
