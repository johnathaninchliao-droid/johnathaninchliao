## 題目（來源：考卷 PDF 第 1–2 頁）

在使用 API 串接生成式 AI 服務時，Token 會影響模型的計費。請問下列何者最正確敘述 Token 在 LLM 應用中的意義？

(A)Token 是模型將文字切分後的基本單位，通常與字詞或子詞對應，文件長度與 Token 數量具有一定關聯性；
(B)Token 是模型用來表示整段文字語意的向量單位，用於理解輸入內容的語意結構；
(C)Token 的數量會影響模型的輸入輸出長度與計費，而上下文長度受限於模型可處理的最大 Token 數量；
(D)Token 只影響模型的運算速度，不影響 API 的使用成本

**官方答案：C（Token 數量影響輸入輸出長度與計費，上下文長度受限於模型可處理的最大 Token 數）**

## 1. 場景與關鍵字（上方）

- 場景：題目以 API 串接生成式 AI 服務的計費情境為背景，要求選出對 Token 在 LLM 應用中「最正確」的意義描述；單據／文件長度與模型上下文限制都與 Token 相關。
- 關鍵字：**Token（詞元）**、分詞（tokenization）、子詞、計費（input／output token）、上下文長度上限、嵌入向量（embedding）與 Token 的區別

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A Token 是切分後的基本單位 | ✅ 本身陳述正確，但非最貼題幹之解 | 分詞確實把文字切成詞或子詞，文件長度與 token 數有關；然而題幹聚焦「計費與上下文」，C 更直接回應提問。建議人工覆核此設計歧義。 |
| B Token 是語意向量單位 | ❌ 錯 | 把整段文字表示為向量的是 embedding（嵌入向量），不是 Token；此選項混淆兩種不同概念。 |
| C Token 影響長度與計費，上下文受最大 Token 限制 | **最正確（正解）** | OpenAI 定價文件以 input／output token 計費；官方文件亦說明上下文窗口以 token 計算且有上限，完整呼應題幹。 |
| D 僅影響速度、不影響成本 | ❌ 錯 | 主流 API 皆按 token 計費，D 與公開定價事實直接矛盾。 |

## 3. 錯置選項（紅框）與未來選答規則

- B 把 Token 與 embedding 混為一談：Token 是文本切分單位，向量是表徵方式，兩者不同層次。
- D 否定 token 計費，與 OpenAI 等公開定價頁面不符。
- **易混淆點（須特別標註）**：A 的定義本身無誤；本題以題幹「Token 會影響模型的計費」與「最正確」限定，判定 C 最貼題意。若人工覆核認為 A 亦應接受，請依考試單位公告為準，本檔不擅自改答案。
- 未來選答規則：題幹出現「計費／成本／上下文長度／最大 Token」時，選同時涵蓋長度與費用的選項；單純的定義句要再看是否為「最正確」。
