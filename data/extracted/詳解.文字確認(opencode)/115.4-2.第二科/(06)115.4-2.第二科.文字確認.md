## 題目（來源：考卷 PDF 第 2 頁）

某物流公司評估導入 No-Code／Low-Code 平台，希望能與現有的 ERP 系統、倉儲管理系統及客戶通知平台進行資料串接。若主要考量系統整合能力，而非介面美觀度或功能豐富性，下列哪一項平台特性最能滿足此整合需求？

(A)平台是否提供強制將所有應用程式部署於地端伺服器的選項，以確保資料不外流；
(B)平台是否具備豐富的 API 介接能力、Webhooks 機制與開放式架構，能順暢串接既有系統；
(C)平台是否內建將圖形化流程還原為原始程式碼的編譯工具，以便未來自行維護；
(D)平台是否採用封閉式架構設計，以降低外部系統整合所帶來的安全風險

**官方答案：B（平台是否具備豐富的 API 介接能力、Webhooks 機制與開放式架構）**

## 1. 場景與關鍵字（上方）

- 場景：物流公司評估導入 No-Code／Low-Code 平台，核心需求是與既有 ERP、倉儲系統、客戶通知平台串接；題幹明確排除介面美觀與功能豐富性，聚焦「系統整合能力」。
- 關鍵字：**系統整合能力**、**API 介接**、**Webhooks**、開放式架構、ERP／WMS 串接、部署選項與封閉架構的取捨

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A 強制地端部署 | ❌ 錯 | 部署位置是資安與資料落地議題，並不保證能與既有系統串接；題幹關心的是整合能力。 |
| B API／Webhooks／開放架構 | **最正確（正解）** | Microsoft 連接器文件與 n8n Webhook 文件皆說明以連接器、API 與事件回呼串接外部系統，正是跨平台整合的關鍵。 |
| C 圖形流程還原原始碼 | ❌ 錯 | 能否還原程式碼關係到可維護性與廠商鎖定，不是「與既有系統串接」的必要條件。 |
| D 封閉式架構降低風險 | ❌ 錯 | 封閉架構通常使外部整合更困難，與題幹的整合需求方向相反。 |

## 3. 錯置選項（紅框）與未來選答規則

- A 把「部署選項」誤當「整合能力」；C 把「可維護性」誤當「串接能力」；D 的封閉設計甚至會阻礙整合。
- 未來選答規則：題幹出現「與既有系統串接／ERP／通知平台／整合」時，首選具備 API、Webhook、開放架構的選項；看到「封閉」通常要警惕。
