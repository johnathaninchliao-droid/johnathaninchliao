## 題目（來源：考卷 PDF 第 10 頁）

某外送平台計畫推出語音訂餐功能。當使用者說出：「幫我點一份雞排便當和珍珠奶茶，送到公司」，系統需完成語音理解、意圖判斷、將需求轉換為結構化指令，並呼叫外部外送服務 API 完成下單，最後回傳訂單狀態與預計送達時間。請問上述系統最核心的技術機制為何？

(A) 將自然語言轉換為可執行 API 呼叫 parameters 之函數呼叫機制；
(B) 透過多輪對話管理維持訂餐流程之任務導向對話系統；
(C) 透過向量資料庫檢索菜單資訊並生成回應之檢索增強生成系統；
(D) 將自然語言轉換為語意結構表示之語意解析技術

**官方答案：A（將自然語言轉換為可執行 API 呼叫參數之函數呼叫機制）**

## 1. 場景與關鍵字（上方）

- 場景：外送語音訂餐——語音辨識後，需把「雞排便當、珍珠奶茶、送到公司」**轉成結構化參數並呼叫外部 API 下單**，再回傳狀態；問「最核心技術機制」。
- 關鍵字：**Function Calling／工具使用（tool use）**、**自然語言→API 參數（JSON arguments）**、OpenAI function calling 官方流程、任務導向對話（多輪管理）、RAG（向量檢索）、語意解析（自然語言→語意表示）；題幹「呼叫外部 API 完成下單」是作答關鍵。

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A 自然語言轉為可執行 API 呼叫參數的函數呼叫機制 | **最正確** | OpenAI function calling 官方流程：模型接收工具定義→產生符合規格的呼叫參數（JSON）→應用程式執行工具→回傳結果；正好對應「轉結構化指令＋呼叫 API 下單＋回傳狀態」。 |
| B 多輪對話管理的任務導向對話系統 | ⚠️ 部分正確但非核心 | 訂餐可能涉及多輪澄清，但題幹強調的是「轉結構化指令並呼叫外部 API 完成下單」；對話管理無法單獨完成 API 參數生成與執行。 |
| C 向量資料庫檢索菜單的 RAG 系統 | ❌ 錯誤 | RAG 用於檢索知識文件再生成回答；本題核心是下單（API 呼叫），不是菜單檢索。 |
| D 自然語言轉語意結構表示的語意解析 | ⚠️ 部分正確但不足 | 語意解析只做到「語意表示」，未涵蓋「產生可執行 API 參數並呼叫工具」的關鍵環節；function calling 是更具體且完整的機制。 |

## 3. 錯置選項（紅框）與未來選答規則

- B 是**著重對話流程而非執行機制**：談的是多輪管理，不是 API 下單。
- C 是**檢索用途錯置**：RAG 不負責交易執行。
- D 是**只做一半**：語意解析生成結構表示，但未走到 API 參數與呼叫；A 完整涵蓋「解析→參數→呼叫→回傳」。
- 未來選答規則：
  1. 看到「自然語言→結構化指令→呼叫外部 API 完成動作」→ **Function Calling**。
  2. 看到「多輪澄清、維持流程」→ 任務導向對話（本題非核心）。
  3. 看到「查知識庫再回答」→ RAG。
  4. 看到「只轉成語意表示、未提到執行」→ 語意解析，屬較不完整選項。
  5. 口訣：**要「做事」就找 function calling／tool use**。
