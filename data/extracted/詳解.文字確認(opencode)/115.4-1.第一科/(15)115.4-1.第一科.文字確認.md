## 1. 場景與關鍵字（上方）

- 場景：從四種資料儲存形式中辨識「結構化數據」。
- 關鍵字：**結構化數據（structured data）**、預先定義 schema、表格（rows/columns）、關聯式資料庫 MySQL、**半結構化（JSON／XML）**、非結構化（純文字對話）。

## 2. 逐項判定（綠框依據）

| 選項 | 判定 | 理由 |
|---|---|---|
| A MySQL 訂單記錄 | **結構化（正解）** | AWS／Microsoft／Oracle 官方定義：結構化資料有預先定義的 schema、以表格行列呈現，關聯式資料庫（如 MySQL）表格即典型例子。 |
| B JSON 商品訂單 | ❌ 半結構化 | JSON 有標籤但無固定關聯式 schema，Oracle／AWS 歸類為 semi-structured。 |
| C XML 產品目錄 | ❌ 半結構化 | Oracle 明確指出 XML 是 semi-structured 的例子。 |
| D 純文字客服對話 | ❌ 非結構化 | 文字對話無固定欄位／格式，屬 unstructured（如社群貼文）。 |

## 3. 錯置選項（紅框）與future選答規則

- B/C 是「半結構化」（有某種結構但不照固定表格 schema），D 是「非結構化」；三者都不是嚴格定義的結構化數據。
- 未來選答規則：
  1. 看到「關聯式資料庫、表格、固定欄位／型別、SQL」→ 結構化。
  2. 看到「JSON、XML、key-value」→ 半結構化。
  3. 看到「純文字、圖片、音訊、影片、對話紀錄」→ 非結構化。
- 本題唯一結構化的是 A。
